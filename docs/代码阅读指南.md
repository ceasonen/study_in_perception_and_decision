# 读仓库：掌握实现与程序组织

源码在 `repositories/`，与 `papers/` 分开保存。每个项目的[学习卡](资源总表.md)提供实际代码入口、模块结构、追踪顺序和编程练习。第一轮阅读不要从整个目录的第一个文件开始，也不要深入所有第三方依赖。

## 一次只读通一条完整链路

```mermaid
flowchart LR
    C[配置与运行入口] --> D[数据或环境]
    D --> B[一个 batch 或一个 episode]
    B --> M[模型 forward]
    M --> L[loss 与学习目标]
    L --> U[梯度、优化器与目标更新]
    U --> V[保存、日志与评估]
```

先从 README 选一个最小任务，确认入口和配置；再顺着一个 batch 或一个 episode 追到输出。读每个模块时记下输入、输出、形状、单位、可变状态与调用者。只有主链路走通以后，再扩大到不同任务、并行训练和数据准备。

要特别区分训练 forward 与部署推理：标签、真实状态、教师信息、未来动作和 oracle 数据是否只用于训练？这既是算法理解，也是接口设计。

## 每个仓库至少做出的五份小记录

若重点是 RL infra，进入[RL 基础设施学习专题](RL基础设施学习专题.md)，按 CleanRL → Tianshou → 对照 SB3 → 按需 MALib 阅读。专题提供当前 Tianshou v2 的 PPO／SAC 调用链、实际文件入口、测试阅读和四个编程练习；不混用旧版接口。

1. **职责图**：哪些模块管数据、模型、优化、执行与评估；注明是直接函数调用还是跨进程通信。
2. **一条数据流**：从一个真实输入追到最终输出，记下关键 shape、dtype、device 与坐标／动作单位。
3. **一次更新**：哪些参数参与哪个 loss，哪里反传，哪里 detach，什么时候更新 target／teacher。
4. **一段状态生命周期**：buffer、RNN hidden state、轨迹缓存、优化器状态或随机数从哪里来，何时重置和保存。
5. **论文到代码的对应表**：核心公式／图中的模块分别落在哪个类、函数和配置，哪些实现细节论文没有写。

从阅读到动手的练习应小而明确。例如抽出 DETR 匹配器的输入输出说明，给 ByteTrack 画状态机，在 DrQ-v2 中解释 encoder 的梯度路径，或者对 ACT 的训练与推理做参数对照。原始源码保留为学习基线，自己的改动另建练习目录，不要为“整理代码”随意重排作者实现。

## 怎样判断已经读懂

你能说清楚运行一个命令后发生了什么、哪个模块负责什么，以及一个预测结果如何进入损失或环境；能指出修改一个参数会影响哪条链路，也知道程序有哪些依赖和隐藏状态。最终可以不照抄整个仓库，写出相应机制的最小解释性实现。

这些仓库分别展示了不同年代、不同目标的工程选择。单文件、面向对象框架、配置驱动和分布式系统各有适用场景，不把某一种组织方法当作所有项目都应照搬的标准。先学会分辨模块职责与接口，再决定自己的代码需要怎样的抽象。

使用[代码笔记模板](templates/代码笔记.md)记录。一开始优先 CleanRL、DETR 和 DrQ-v2；论文层面的学习目标另见[论文阅读指南](论文阅读指南.md)。
